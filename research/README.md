# Научный код, который можно читать сверху вниз

Это маленькое рабочее PyTorch-ядро для будущего метода: **извлечение → голова → прогноз**.
Оно не скачивает LLM, не читает датасет и не запускает конкурсную отправку.
Существующие baseline сохранены. Начинай с [method.py](method.py).

## Один пример целиком

Обвязка уже дала `batch`: два массива `input_ids` и `attention_mask` формы `[B,T]`.
`B` — число задач сейчас, `T` — общая длина с padding (добавленными пустыми позициями).
Она также загрузила LLM и обученную голову. Эти объекты приходят аргументами,
поэтому в научной функции нет путей, pickle, загрузки весов или чтения файлов.

В `method.py` сначала вызывается `extract_features`. Теперь открой [features.py](features.py):
там виден **сам forward LLM**, а не скрытый класс-извлекатель. Мы просим hidden_states,
выбираем заданные индексы и для каждой задачи находим последний токен с единицей в маске.
Слева и справа padding работает одинаково: не используем неверное для левого padding
`mask.sum()-1`. Индексы относятся к tuple hidden_states, не автоматически к номерам блоков.

После среза на одном слое `[B,T,D]` становится `[B,D]`. Из K таких векторов строим
`[B,K,D]`. Например, при B=2, K=3, D=4 форма `[2,3,4]`: две задачи, три слоя,
четыре координаты. Это игрушечные размеры для понимания, не параметры конкурсной LLM.
LLM проходит вперёд без расчёта градиентов; признаки отделены от её графа.

Возвращаемся в `method.py`: `predictor(x)` преобразует эти признаки в одно число
на задачу. **Где архитектура?** В [predictor.py](predictor.py), прямо в `build_predictor`:

```text
width=0: [B,K,D] → Flatten → [B,K*D] → Linear(K*D,1) → [B,1]
width>0: то же → Linear(K*D,width) → ReLU → Linear(width,1)
```

Никакого дерева поиска архитектур здесь нет. `width` — число нейронов скрытого слоя.
Последнее число — logit, ещё не вероятность. В `method.py` sigmoid переводит его
в [0,1], порог 0.5 даёт True/False. Это модельная оценка, не обещание калиброванной
вероятности. При равенстве порогу здесь True — правило записано явно.

**Откуда взялись веса головы?** [train.py](train.py) получает только обучающие X и y.
В цикле: predictor → BCE (ошибка бинарного прогноза) → backward → optimizer.step.
LLM в этом цикле вообще нет. Функция не умеет сама отделять train от validation:
этот научно важный выбор фиксирует команда ДО обучения. Настройки, выбор слоя,
нормировка и порог не подбираются на окончательной проверочной выборке.

## Что можно менять как исследователь

Другие состояния/разности/косинусы — features.py. Другую голову — predictor.py.
Другую целевую функцию — train.py. Порядок научных операций — method.py.
Смена checkpoint/template/обрезания влияет на X и требует нового feature_spec и кеша.
«Спрятать загрузку» не значит скрыть эти параметры от проверки.

## Что уже можно запускать

```bash
python -m unittest discover -s research/tests -v
```

Это CPU-тесты с маленькими тензорами и подставной LLM, а не эксперименты на AIMO.
Не заявляется, что появился хороший классификатор, данные или готовый solution ZIP.
Следующая инженерная задача — адаптер токенизации/кеша/разбиения и тонкий `solution.py`,
который импортирует этот же код. Его надо проверить в отдельном коммите с реальным
checkpoint и бюджетом. Не копировать корень проекта в solution ZIP: вложенные импорты
и доступность модулей проверяются в чистом распакованном архиве.
