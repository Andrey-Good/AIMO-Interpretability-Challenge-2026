# Как работать с AIMO через агентов

Начинай с [научного кода](../../research/README.md), не с конфигураций.
`method.py` показывает весь путь, `features.py` — извлечение, `predictor.py` — голову,
`train.py` — обучение только головы. Сейчас это проверяемое ядро, **не готовый GPU-конвейер**.

Для пользователя достаточно поставить вопрос: «Что берём у LLM, как обрабатываем,
чем предсказываем и с чем сравниваем?» Агент обязан превратить это в ограниченный опыт,
а не просить тебя разобраться в путях и сериализации.

## Первый запуск в своём Codex

Открой корень репозитория. Проверь доверие к проекту, `codex --version`, доступные
модели через `/model`, навыки через `/skills` в CLI и наличие именованных подагентов.
Настройки проекта не превосходят ограничения аккаунта/администратора или явные настройки сессии.
В приложении используй доступные селекторы моделей/навыков; названия интерфейсов могут различаться.

Первое поручение:

> Прочитай AGENTS.md и MEMORY/STATE.md. Используй aimo-data-audit и aimo-research-cycle.
> Сначала выясни схему доступных данных, число независимых задач и правильное разбиение.
> Подготовь один маленький опыт по слоям и смету вычислений. Не запускай GPU,
> не скачивай веса и не обращайся к платным API. Научную часть покажи через research/method.py.

Для сложного планирования выбери Astra и high через `/model` в CLI.
Обычный запуск с моделью можно задать явно: `codex -m gpt-6-astra`.
Именованные CLI-профили теперь являются отдельными пользовательскими файлами
`~/.codex/<имя>.config.toml`, не `[profiles.*]` в конфигурации проекта.
Этот коммит не изменяет твой пользовательский config и не создаёт такие профили.

Это не вызов оплачиваемого API из проекта: настройки относятся к уже установленному Codex.
Никакие ключи в репозиторий не добавлены. Сначала измерьте фактический расход аккаунта.
