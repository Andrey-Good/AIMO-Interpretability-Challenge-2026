# 4. От понимания к своему методу

[Назад](03-uncertainty.md) · [Начало](../README.md)

## Где проходит граница твоей работы

Твоя территория — отдельная папка `solutions/my-method/`. В её корне лежит `solution.py` с `are_robust(model_id, problems)`. Вспомогательные модули и обученные артефакты находятся рядом. Исходные baseline лучше сохранить для сравнения. Обучающие данные, логи и кеши держи **вне** папки отправки.

`components/` описывает проверяющую сторону. Переписывание scoring у себя не улучшает результат на сервере. В `scripts/` обычно меняется организация локальной работы, а не исследовательская идея.

## Идея → конкретные изменения

**Другой слой или другой способ собрать представление.** В копии probe меняется `_encode_problem`. Вместо одного токена можно, например, усреднять допустимые позиции: `[B,T,D] → [B,D]`. Это уже новый метод, не поведение baseline. При padding среднее должно учитывать `attention_mask`; нельзя усреднять добавленные пустые позиции вместе с настоящим текстом. После изменения нужно заново собрать признаки и обучить пробу. Индекс слоя, checkpoint и промпт необходимо сохранить вместе с весами.

**Несколько слоёв сразу.** Пусть берутся `K` состояний ширины `D`. Конкатенация даёт `[K*D]`, а усреднение — `[D]`. Эти операции различаются: конкатенация сохраняет отдельные координаты каждого слоя, усреднение смешивает их. Старые веса `[S,D]` не подходят для `[K*D]`. Потребуются новый extractor, обученный предсказатель и согласованная схема артефакта.

**MLP вместо линейной пробы.** Извлечение `h:[D]` можно оставить, но заменить scorer, обучение и загрузку артефакта. В PyTorch, например, `Linear(D,H) → ReLU → Linear(H,1)`. Для бинарного обучения возможен `BCEWithLogitsLoss`, принимающий logits, не заранее применённый sigmoid. Это вариант нового решения; в исходном representation baseline такого обучения нет. Не пытайся положить веса MLP в старый `.pkl` и вызвать `mean_ensemble_margin`: он реализует совсем другую формулу.

**Новый признак uncertainty.** Если он вычисляется из уже собранных рядов, начни с `metrics.compute_generation_confidence_metrics`; если нужна новая информация на каждом шаге — с `GenerationConfidenceCollector`. Затем меняются `FEATURE_NAMES`, обучение и артефакт. Проверка в `artifact.py` требует точного совпадения порядка признаков. Добавить поле только в возвращаемый словарь недостаточно: без включения в схему оно не попадёт в предсказатель.

**Другой регрессор или порог.** Для uncertainty смотри `build_candidate_specs`, `build_pipeline`, `select_threshold` и `run_model_selection` в training script. Порог подбирается по доступной валидации, не по скрытым меткам. Увеличение числа перебранных вариантов требует более аккуратной проверки, а не гарантирует улучшение.

## Как соотносятся обучение и отправка

```text
ЛОКАЛЬНО / НА ОБУЧАЮЩЕМ СЕРВЕРЕ
задачи + доступные метки → признаки → разделение по группам
→ обучение и выбор настроек → сохранённый артефакт

ВО ВРЕМЯ ОЦЕНКИ
model_id + новые строки → те же признаки → загруженный артефакт
→ прогнозы → list[bool]
```

Общее между двумя путями — определение признаков, не метки и не сохранённые ответы. Веса LLM в этих baseline фиксированы; обучаемый компонент находится после неё. Для representation-probe полный training pipeline придётся написать отдельно. Для uncertainty оба подготовительных скрипта уже есть; их команды и параметры описаны в [оригинальном README](../../solutions/uncertainty-profiling/README.md).

Менять только `batch_size` — обычно оптимизация ресурсов, менять промпт, checkpoint, слой или набор токенов — изменение самих признаков. Но и после изменения батчинга сравни реальные результаты: padding, обрезание и численные различия способны нарушить ожидаемую эквивалентность.

## Проверка без ложного ощущения успеха

Сначала запусти [лёгкий проход через evaluator](../labs/01_contract.py). Для настоящих данных учти [несовпадение формата импортёра](../reference/pitfalls.md), затем вызывай существующий runner, например для своей папки:

```bash
python scripts/run_local.py solutions/my-method --input-dir data/val-sample-text/input --reference-dir data/val-sample/reference
```

Это команда для уже подготовленного окружения. `my-method` и нормализованные данные должны существовать; guide не создаёт якобы готовое конкурсное решение. Подмена `python` на `uv run` позволяет запускать в окружении проекта, но может сначала синхронизировать зависимости.

При `coverage < 1` сначала вызывай свой `are_robust` непосредственно: так увидишь исключение, которое ingestion скрывает. При `coverage == 1` проверь ещё, что действительно был найден и применён артефакт, а не сработала ветка «все False». Сравни результат с простыми константными baseline и повторным запуском.

Сборщик поддерживает подходящий для этого snapshot режим `components`:

```bash
python scripts/build.py components --input-dir data/val-sample-text/input --reference-dir data/val-sample/reference
python -m zipfile -l dist/solution-my-method.zip
```

Он создаёт архивы всех папок `solutions/` и служебных компонентов. Для отправки нужен **только свой solution ZIP**, где `solution.py` лежит прямо в корне. Не выбирай `all`: в текущем дереве отсутствуют некоторые организаторские шаблоны, которые он требует. Сборщик копирует содержимое папки решения, поэтому отдельно проверь отсутствие данных, секретов, окружений и лишних больших файлов.

По описанию в [исходном README](../../README.md), сервер работает без сети и не устанавливает твой `requirements.txt`. Зависимости контейнера задаёт [`Dockerfile.competition`](../../Dockerfile.competition), локальные — [`pyproject.toml`](../../pyproject.toml). Успешная CPU-лабораторная не проверяет вместимость LLM, длительность inference и совместимость сериализованного estimator с конкурсным контейнером.

## Когда цель изучения достигнута

Ты должен уметь для своей идеи назвать: **входной объект; форму признаков; функцию, которая их создаёт; обучаемые параметры; способ проверки на новых задачах; содержимое артефакта; правило превращения score в `bool`.** Если один пункт остаётся «какая-то магия библиотеки», вернись только в соответствующий раздел, а не перечитывай весь репозиторий.
