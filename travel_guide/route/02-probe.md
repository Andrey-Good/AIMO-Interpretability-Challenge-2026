# 2. Representation probe: один вектор вместо решения

[Назад](01-contract.md) · [Начало](../README.md) · [Далее](03-uncertainty.md)

Основной файл — [`probe_inference.py`](../../solutions/trained-probe/probe_inference.py). [`solution.py`](../../solutions/trained-probe/solution.py) только переадресует вызов в `predict_robustness`. **Этот baseline вообще не генерирует ответ:** ему хватает одного прохода LLM по промпту.

## Порядок вызовов

```text
predict_robustness(model_id, problem_texts)
  ├─ _load_artifact(model_id)
  └─ для каждой строки: _predict_problem
       ├─ _encode_problem
       │    _load_model → _build_prompt → tokenizer → model(...)
       │    → hidden_states[layer][0, -1, :]
       ├─ mean_ensemble_margin (или старый _single_probe_margin)
       └─ bool(margin >= 0)
```

**Артефакт** — сохранённый результат обучения небольших проб плюс настройки: веса, смещения, пороги, слой, checkpoint и системный промпт. Это не веса LLM и не готовые ответы на тестовые задачи. Без найденного артефакта метод возвращает все `False` и даже не начинает извлекать представления.

## Текст становится тензорами

`_build_prompt` добавляет сохранённый системный промпт. При наличии системного промпта код пытается применить chat template: шаблон с маркерами ролей пользователя и ассистента. При неудаче остаётся простая склейка строк; без системного промпта — исходный текст задачи. Эти ветки **не обязательно эквивалентны** по токенам.

```python
model_inputs = tokenizer(prompt, return_tensors="pt", truncation=True)
```

Токенизатор превращает текст в номера токенов. Это не обязательно слова: один математический символ или число может разбиться на несколько частей. `model_inputs` — объект, похожий на словарь. В нём обычно есть `input_ids` и `attention_mask`, каждый формы `[1, T]`, где `T` — число токенов после форматирования и обрезания. `**model_inputs` разворачивает словарь в именованные аргументы обычного вызова `nn.Module`.

`model(...)` здесь вызывается с `output_hidden_states=True`, `use_cache=False` и под `torch.no_grad()`. Первое просит промежуточные представления; второе отключает KV-кеш, нужный прежде всего для продолжения генерации; третье не строит граф для обратного прохода. Отдельный `model.eval()` задаёт режим оценки. `eval()` и `no_grad()` решают разные задачи и не заменяют друг друга.

Результат `output.hidden_states` — **tuple тензоров**, не один четырёхмерный тензор:

```text
hidden_states = (H_0, H_1, ..., H_L)
каждый H_l: [1, T, D]
```

`L` — число transformer-блоков, `D` — ширина представления. Нулевой элемент обычно соответствует входным embedding-представлениям; далее идут состояния слоёв. Точное место нормализации зависит от архитектуры. Поэтому индекс tuple нельзя без проверки переименовать в «номер блока», особенно при переходе к hooks. [Описание выходов Transformers](https://huggingface.co/docs/transformers/main_classes/output).

### Что делает `[0, -1, :]`

```python
vector = hidden_states[layer_index][0, -1, :]
```

Сначала выбран один слой. `0` выбирает единственную задачу; `-1` — последнюю позицию **всего отформатированного промпта**; `:` оставляет все `D` координат. Итого `[1, T, D] → [D]`, а не `[1, D]`. При chat template последней позицией может быть служебный токен начала ответа, а не последний символ условия.

Почему эта позиция полезна? В причинной модели она может учитывать предшествующий промпт через attention. Но это лишь доступный вектор признаков, не доказательство, что в нём содержится «всё понимание задачи». Вызовы `.detach().float().cpu().numpy()` отделяют тензор от графа, приводят к float32, переносят на CPU и превращают в NumPy-массив для маленького предсказателя.

## Что такое линейная проба

Проба — небольшой обученный «считыватель» информации из представления. Для одной задачи:

$$
h\in\mathbb R^D,\quad w\in\mathbb R^D,\quad s=w^\top h+b,\quad m=s-\tau.
$$

`w` задаёт, какие координаты учитываются и с каким знаком; `b` — смещение; `τ` — сохранённый порог; `m` — подписанное расстояние **по шкале score** до порога. Не путай его с евклидовым расстоянием или вероятностью. Здесь нет обязательного `sigmoid`: решение принимается по знаку margin.

В основном `.pkl`-формате проб несколько: они сгруппированы, например, по фолдам, а внутри группы представлены разными seed. Seed — начальное состояние случайности при обучении. Для каждой группы на выбранном слое:

```text
weights W: [S, D]   vector h: [D]
W @ h: [S]         bias b: [S]   threshold tau: [S]
margins = W @ h + b - tau: [S]
```

`S` — число проб в этой группе. Затем код собирает margins **всех подходящих проб всех групп** в один список и берёт среднее. Если размеры групп различаются, группы не имеют равного веса: каждая отдельная проба имеет равный вес.

$$
\bar m=\frac1M\sum_{j=1}^M(w_j^\top h+b_j-\tau_j),\qquad
\widehat y=\mathrm{bool}(\bar m\ge0).
$$

Например, `h=[1,2,-1]`. Первая проба: `w=[0.5,-1,2]`, `b=0.2`, `τ=0.3`, значит `m=-3.6`. Вторая: `w=[-1,1,-0.5]`, `b=1`, `τ=0.1`, значит `m=2.4`. Среднее `-0.6`: ответ `False`. Это **не голосование большинством**. Для margins `[1,1,-5]` большинство знаков положительное, но метод всё равно выдаст `False`.

## Что здесь обучается и что менять

В этой папке есть код **применения**, но нет скрипта обучения representation-probe. Нельзя искать здесь скрытый `optimizer.step()` или считать, что запуск `solution.py` обучит новый артефакт. Для своего обучаемого считывателя нужно отдельно собрать векторы и метки, обучить модель, сохранить настройки и воспроизвести те же признаки при inference.

Выбор слоя задаётся `_layer_index`: для `.pkl` приоритет у `recommended_strategy.layer_index`, иначе используется `best_layer_index`. Менять слой без переобучения проб недостаточно: совпадение формы `[D]` не означает совпадение смысла координат. То же относится к checkpoint, шаблону промпта и способу выбора токена.

Ещё одна важная особенность текущего исходника: `_encode_problem` вызывает `_load_model` **для каждой задачи**. Это возможное узкое место, а не необходимая часть метода. При оптимизации загрузку можно вынести из цикла, сохранив соответствие модели, dtype, промпта и слоя. В guide этот код намеренно не исправлен.

### Проверка понимания

Почему последнее состояние не является последним сгенерированным токеном? Почему смена слоя может не вызвать ошибку shape, но испортить прогноз?

<details><summary>Ответ</summary>

Генерации в этом пути нет: последний токен принадлежит входному промпту. У разных слоёв может быть одинаковая ширина `D`, но разные распределения и смысл признаков; прежние веса проб обучались не на новых состояниях.

</details>
