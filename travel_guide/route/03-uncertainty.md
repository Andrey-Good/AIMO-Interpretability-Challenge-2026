# 3. Uncertainty profiling: как модель выбирает токены

[Назад](02-probe.md) · [Начало](../README.md) · [Далее](04-your-method.md)

Этот метод, в отличие от probe, **генерирует продолжение**. Он изучает не правильность полученного текста напрямую, а распределения, из которых модель выбирает следующие токены. Из них получаются 14 чисел на задачу; небольшой регрессор предсказывает величину ухудшения точности. Малая предсказанная величина означает прогноз устойчивости.

## Путь исполнения и обозначения

```text
solution.are_robust → inference.predict_robustness
  alias → checkpoint → artifact → загрузка LLM один раз на вызов
  → extraction.extract_generation_features
      → iter_generation_feature_batches → model.generate
          → GenerationConfidenceCollector на каждом шаге
      → metrics.compute_generation_confidence_metrics
  → DataFrame [N, 14] → estimator.predict → scores [N]
  → [bool(score < decision_threshold), ...]
```

[Все эти файлы](../reference/files.md) находятся в `solutions/uncertainty-profiling/`. `N` — число входных задач; `B` — небольшой фактический батч; `T` — длина дополненного padding-промпта; `G` — число шагов генерации; `V` — размер словаря.

[`config.py`](../../solutions/uncertainty-profiling/uncertainty_profile/config.py) переводит alias `qwen3-8b:low` в `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B`. Alias — имя модели в соревновании, не обязательно имя репозитория весов. В отличие от probe, здесь эта подстановка явная.

Настройки inference читаются **из артефакта**. Значения по умолчанию в классе конфигурации: до 2048 токенов промпта, до 4096 новых токенов, batch size 8, `do_sample=False`, static KV-cache. Это пределы, а не гарантированные длины. Изменение default в `config.py` само по себе не переписывает настройки сохранённого артефакта.

## От logits к вероятностям

На очередном шаге collector получает `scores: [B, V]`: по одному числу-кандидату для каждого токена словаря. Числа ещё не обязаны лежать между нулём и единицей. Для одной строки:

$$
p_t(v)=\frac{\exp z_t(v)}{\sum_u\exp z_t(u)},\qquad
\ell_t(v)=\log p_t(v).
$$

В коде используется устойчивый `log_softmax(scores.float(), dim=-1)`, а вероятности получаются через `.exp()`. `dim=-1` означает нормировку **по словарю**, отдельно для каждой задачи и шага. Collector наблюдает scores в своей точке pipeline генерации; они могут уже отражать другие logits processors, поэтому это не универсальное обещание «сырых logits до всех преобразований».

Если выбран токен `a_t`, нам нужно одно число `ℓ_t(a_t)`, а не весь словарь. Для батча это делает:

```python
selected = log_probs.gather(-1, token_ids.unsqueeze(-1)).squeeze(-1)
# [B,V]                 [B] → [B,1]                     → [B]
```

`gather` берёт в каждой строке столбец с её собственным ID. Если `token_ids=[2,0]`, берутся `log_probs[0,2]` и `log_probs[1,0]`. ID — индекс столбца, не вероятность. В конце шаги складываются в `[B,G]`; padding и EOS, то есть конец ответа, исключаются маской.

### Почему collector отстаёт на один шаг

`GenerationConfidenceCollector.__call__` вызывается **перед выбором следующего токена**. Сейчас известно распределение шага `t`, но выбранного токена `a_t` в `input_ids` ещё нет. Поэтому сохраняется `pending_log_probs`. При следующем вызове последний токен `input_ids[:, -1]` уже является предыдущим выбором, и его вероятность можно извлечь из сохранённого распределения. Последний токен отдельно обрабатывается в `compute_features`, потому что следующего вызова может не быть.

Это не attention hook и не вмешательство в ответ: collector возвращает `scores` без изменений. [Точный код с комментариями](../annotated/collector_core.py).

## Три разных вида уверенности

**Вероятность выбранного токена** отвечает: «Насколько модель ожидала именно то, что выдала?» Её отрицательный логарифм — `NLL`. Для вероятности `0.5` NLL примерно `0.693`; для `0.01` — `4.605`. Маловероятный выбор даёт большее наказание.

**Энтропия** учитывает весь словарь:

$$
H_t=-\sum_{v=1}^V p_t(v)\log p_t(v).
$$

Два распределения могут иметь одинаковую вероятность выбранного токена, но по-разному распределять остаток вероятности. Энтропия различает эти случаи. При четырёх равновероятных токенах она равна `ln(4) ≈ 1.386`; при почти однозначном выборе близка к нулю. Логарифмы здесь натуральные, поэтому единица — нат.

**Top-2 margin** — разность вероятностей первого и второго кандидатов. Для `[0.7,0.2,0.1]` это `0.5`; для `[0.36,0.35,0.29]` — `0.01`: лидер есть, но почти не отделён от альтернативы. Это не тот margin, который использовала линейная проба.

## Как получаются именно 14 признаков

[`metrics.py`](../../solutions/uncertainty-profiling/uncertainty_profile/metrics.py) сворачивает последовательность валидных токенов в статистики. Ниже суффиксы имён; в коде у каждого стоит префикс `generation_`.

**Первые восемь:** `mean_logprob`, `mean_prob`, `mean_nll`, `ppl`, `min_logprob`, `max_logprob`, `std_logprob`, `min_k_logprob`. Это средние, крайние значения, разброс и оценка самых маловероятных участков. Для `n` оставшихся токенов:

$$
\mathrm{mean\_nll}=-\frac1n\sum_t\ell_t(a_t),\qquad
\mathrm{ppl}=\exp(\mathrm{mean\_nll}).
$$

Perplexity — экспонента среднего NLL, не процент ошибочных ответов. Если каждый выбранный токен имел вероятность `0.5`, она равна `2`. В общем случае `mean_prob` **не** равен `exp(mean_logprob)`.

Для Min-K логарифмы сортируются от меньших к большим и усредняются первые `k=max(1, ceil(0.2*n))`. Например, из десяти логарифмов берутся два самых отрицательных. Это худшие по вероятности позиции, не первые 20% текста. NumPy `std` здесь использует `ddof=0`.

**Остальные шесть:** `mean_entropy`, `mean_top1_prob`, `mean_top2_margin`, `frac_selected_is_top1`, `frac_high_conf_tokens`, `frac_low_conf_tokens`. Последние две — доли выбранных токенов с вероятностью соответственно `>=0.9` и `<=0.1` при стандартных настройках.

`generation_num_tokens` тоже возвращается из функции, но **не входит** в `FEATURE_NAMES` и в 14 входных столбцов регрессора. При пустом ответе после маскирования число токенов нулевое, непрерывные признаки — `NaN`; далее обученный pipeline заполняет пропуски. При greedy decoding `frac_selected_is_top1` обычно равна единице: не стоит автоматически считать каждый из 14 признаков независимым полезным сигналом. Кроме того, `mean_nll` точно дублирует `-mean_logprob`, а `ppl` является их преобразованием.

[Пример с настоящей функцией metrics и маленькими распределениями](../labs/03_uncertainty.py).

## Регрессор, порог и обучение

[`inference.py`](../../solutions/uncertainty-profiling/uncertainty_profile/inference.py) создаёт DataFrame **в порядке `artifact.feature_names`**. Обученный `estimator.predict` возвращает `[N]`. Решение — строго `score < decision_threshold`; при равенстве ответ `False`. Это score предсказанного decay, **не вероятность устойчивости**. Чем он меньше, тем лучше — знак сравнения противоположен probe.

[`compute_uncertainty_features.py`](../../solutions/uncertainty-profiling/scripts/compute_uncertainty_features.py) отдельно генерирует признаки для исходных задач и сохраняет Parquet-кеш. Повторные тексты генерируются один раз, после чего исходные строки восстанавливаются. Поэтому число строк обучения может превышать число уникальных промптов.

[`train_uncertainty_regressor.py`](../../solutions/uncertainty-profiling/scripts/train_uncertainty_regressor.py) обучает не LLM, а `SimpleImputer → regressor`. Цель регрессии — готовый столбец `absolute_accuracy_decay`, метка для подбора порога — `model_is_robust`. Их формирование этот скрипт не воспроизводит. Кандидаты — Extra Trees, Random Forest и HistGradientBoosting.

Для проверки строки разбиваются на фолды с группировкой по `original_problem`. Модель обучается на одних группах и предсказывает на других; так получаются **out-of-fold** прогнозы для всех строк. Если копии одной задачи попадут с обеих сторон разбиения, оценка может отражать запоминание, а не перенос на новые задачи.

По этим прогнозам подбираются регрессор и порог; победитель заново обучается на всех доступных обучающих строках и сохраняется в `.joblib`. Важно: выбор оптимизирует сначала balanced accuracy — среднюю долю верных ответов отдельно по двум классам, — а внешний scoring считает обычную accuracy. И подбор лучшего варианта на тех же OOF-результатах не превращает их в независимый финальный тест. Подробнее — [риски оценки](../reference/pitfalls.md).

### Проверка понимания

Почему нельзя поменять длину генерации и автоматически считать старый регрессор подходящим? Почему collector не хранит `[B,G,V]`?

<details><summary>Ответ</summary>

Меняется распределение признаков, на которых регрессор был обучен. Collector сразу сворачивает словарь в несколько чисел и сохраняет полный массив log-probabilities только для одного ожидающего шага. Его статистики занимают порядка `B*G + B*V`, но память самой LLM и KV-кеша этим не отменяется.

</details>
