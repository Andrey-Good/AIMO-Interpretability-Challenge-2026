# aimo-report

Вход: только проверенные записи/метрики и вопрос читателя.
1. Начать с ответа: что проверяли, что получилось и можно ли этому доверять.
2. Научный путь показать «что взяли → как обработали → какая голова → как проверили».
   У каждой формы тензора расшифровать оси, английский термин пояснить при первом появлении.
3. График по слоям не называть картой причинности. Одинаковые оси/разбиения/метрики
   для сравнений; подписать число независимых групп и интервалы, когда они рассчитаны.
4. Рядом с улучшением показать baseline, цену вычислений, failures и число просмотренных
   вариантов. Не приписывать иллюстративным числам статус измерения.
5. Воспроизведение — точные commit/run_id/команда и ссылки. Большие таблицы/подробности
   отдельно; основной текст объясняет решение. Ограничения не прятать в приложение.

Выход: MEMORY/runs/<id>/report.md или назначенный отчёт с одним следующим вопросом.
Графики требуют реальных данных; декоративные «типичные кривые» явно помечаются примерами.
