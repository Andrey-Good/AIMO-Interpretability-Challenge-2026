# aimo-feature-extraction

Вход: гипотеза и feature_spec: checkpoint/revision, tokenizer/template, слои,
позиции, маски, обрезание, dtype, настройки генерации и порядок выходных осей.
1. Показать путь на одном примере: текст → токены → LLM → выбранные состояния → признаки.
2. Изменять research/features.py либо изолированный модуль направления; держать
   математику видимой, не прятать в фабрике. Общий контракт требует владельца.
3. Для [B,K,D] объяснить B=задачи, K=выбранные слои, D=ширина состояния.
   Последний валидный токен находить по маске, не автоматически [:,-1,:].
4. Не смешивать состояния промпта и сгенерированного ответа; сохранять соответствие
   выбранного токена его распределению. Исключение EOS/PAD объявлять явно.
5. LLM заморожена; отделить train/eval головы. Проверять пустую/неверную маску,
   обе стороны padding, порядок примеров, NaN и совпадение индивидуального/батчевого расчёта.
6. Кеш связывать с feature_spec+revision+IDs; не переиспользовать после изменения
   промпта/слоя/генерации только потому, что формы совпадают. Не коммитить активации.

Выход: функция, описание осей и smoke-тесты на маленьких известных тензорах.
Большой прогон выполняется отдельно через согласованную карточку.
