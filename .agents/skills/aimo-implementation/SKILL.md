# aimo-implementation

Обычно роль aimo-builder (Terra medium); сложный баг — high с причиной.
Вход: договорённые функции, формы, разрешённые пути, тестовые ожидания, запрещённые изменения.
1. Прочитать только нужный путь исполнения и действующие правила.
2. Реализовать минимальный явный код. Извлечение отдельно от головы, обвязка отдельно
   от математики. Нельзя прятать новый отбор токенов/слоёв в «служебный helper».
3. Для дефекта сначала воспроизвести ожидаемый failure; для новой формулы — ручной
   маленький пример и автоматическая проверка. Не подгонять ожидание под текущий ответ кода.
4. Не менять зависимости, evaluator, dataset split или общий API без согласования.
5. Запустить относящиеся к изменению тесты, проверить diff. Не утверждать, что
   реальный GPU inference прошёл, если использована подставная маленькая модель.

Выход: изменённые файлы, контракт, команды/исходы и непроверенные риски.
Никаких новых подагентов, платных API, больших запусков или автоматического push.
