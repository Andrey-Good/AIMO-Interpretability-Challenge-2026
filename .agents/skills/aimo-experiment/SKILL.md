# Провести нужный опыт

Это компактная процедура этого проекта, не внешняя универсальная система запусков.
Работай с текущим согласованным вопросом: можно вернуться к данным/коду, прервать или
сократить опыт в разрешённых пределах. Не требуй отдельного approval.json или плана на каждый тест.
Разрешение на ограниченную серию действует на всю серию; новый бюджет/данные/метки требуют согласования.

Практический интерфейс: `python -m research.experiment --help`.
`prepare` читает локальный JSON/JSONL/Parquet и разделяет family_id; не скачивает данные.
Ожидаются problem/is_robust/family_id либо original_problem/model_is_robust/dataset_id/problem_id.
Сначала проверь, что family_id действительно объединяет перефразы. `prepare` делает только
случайное групповое разбиение: для иных исследовательских вопросов используй явные свои файлы.
Смешанные модели/противоречивые метки не «лечить» произвольным удалением строк.

`run` получает train/validation, LLM, слои, длину/шаблон, голову и предел времени.
Проверь доступные версии/память/GPU. Модель читается только локально; ничего не скачивать
без разрешения. Кеш повторно используется при совпадении определения признаков и входа.
При другой голове не надо повторять LLM. При другой токенизации/длине/слоях это уже другой кеш.
Локальные weights для идентичности хешируются: это может быть заметным дисковым чтением.

Ограничение времени кооперативное: проверяется между батчами/эпохами, не прерывает зависший
CUDA-вызов. Для автономного тяжёлого опыта добавь реальный таймаут процесса средствами среды.
Lock действует только на worktrees одного Git-репозитория; другие клоны/машины требуют координации.
При оставшемся running/lock сначала выясни, жив ли процесс; не удаляй запись/lock вслепую.
При NaN/OOM/утечке прекрати текущую серию; повтор получает новый ID, не затирает failure.

`experiments/<id>/result.json` — небольшой общий журнал; .runtime — кеш/веса/прогнозы/исходники.
После опыта проверь результат и приватность, при необходимости добавь несколько строк notes.md,
закоммить запись/код. Это не коммит на каждую команду. Dirty-опыт имеет снимок исходников и
явную пометку; для подтверждающих опытов предпочитай зафиксированный код. Сохраняй отрицательные итоги.
`export` берёт исходники именно завершённого запуска и голову. ZIP не содержит данных/журналов.
Перенос между версиями библиотек/моделями требует отдельной проверки; сборка не равна приёму Codabench.
