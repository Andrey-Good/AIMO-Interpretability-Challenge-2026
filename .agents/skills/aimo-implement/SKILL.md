# Понятная реализация

Адаптация systematic-debugging и dispatching-parallel-agents из Superpowers;
[источники](../SOURCES.md). Здесь нет обязательного четырёхфазного ритуала.

Работу передавать worker (Terra medium) с контрактом входа/выхода и назначенными файлами.
Научная часть остаётся в features.py, predictor.py, experiment.py; _support.py обслуживает
файлы, загрузку и CLI. Не вводи фабрики, реестры и новый framework без конкретной необходимости.
Параметры, меняющие эксперимент, должны быть видны человеку, даже если IO скрыт.

Если встретил ошибку, проследи плохое значение до источника и воспроизведи на малом примере.
Проверь traceback, входные формы и последние изменения. Не наращивай случайные исправления.
При неясной причине верни координатору пример и факты; он подключит researcher.
Не меняй ожидания теста только потому, что программа вернула другое число.

Для новой математики проверь ручной пример, оси, маски, порядок задач и отсутствие градиентов
LLM. Для обучения — отдельные метки, train-only преобразования и одинаковый путь признаков
при применении. Для экспорта — импорт в чистой папке, без PYTHONPATH исходного репозитория.
Выбирай проверки по изменению; успешный старый тест не покрывает новую ветку исполнения.

Исполнители работают в непересекающихся файлах либо разных worktrees. Верни координатору
изменения, реально выполненные команды, исходы и ограничения. Не дублируй их в трёх отчётах.
Чужое «готово» не заменяет чтение diff и проверку. GPU/публикация — только в пределах поручения.
